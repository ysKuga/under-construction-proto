# docs/evaluation

ゲーム性の評価基準。以下の軸で評価する。

- [おもしろみ](#おもしろみ) — ゲームに含まれる面白さの種類
- [体験品質](#体験品質) — その面白さがどう体験されるか(不快を発生させない工夫)
- [ゲーム理論](#ゲーム理論) — メカニクス構造の分析軸

`docs/concept/ideas/` から内容が固まった項目として切り出し。

## おもしろみ

全要素を満たす必要はない。最低限いずれか1つに該当していれば良い。

以下要素が考えられる。

- `成長`
- `挑戦`
- `経営`
- `工夫`
- `探求`
  - 収集や踏破など
- `競争`
- `協調`
  - 競争の対概念。他者との協力による成果達成
- `没入`
  - 世界観・物語への没入度
- `自己表現`
  - カスタマイズ・ビルド構築による個性の反映
- `発見の驚き`
  - 探求(既知の目標への到達)とは異なり、偶発性・予測外の要素によるもの

### 能力の向上や手段の拡充などできることが増えていく過程

### ゲームを繰り返し遊んだ際に序盤に面白みを感じる点

#### やりくりなどの経営的な点

内容を把握しているからこそ要素への組み合わせなどを深堀しようとする。

- 工夫のしどころを用意できるかどうか

#### 育成方針と難易度

- 難易度の緩やかな上昇
  - 選択肢を検討して手作りを優先
- 急迫の難易度
  - 状況の打開のため最優先事項を定義して果断な取捨選択を実施

### プレイスタイル

近距離、遠距離などのスタイルなどの選択肢の有無により以下が考えられる。

- ユーザーの適正
- 熟達時の発展先
  - モンハンで別武器を使うようなもの

## 体験品質

「おもしろみ」の中身とは別の軸。ユーザーにとっての快適性、不快を発生させない工夫についての観点。

- `達成感の演出`
  - 成長そのものでなく、成長を実感させる見せ方(フィードバック設計)
- `繰り返し耐性`
  - 繰り返される演出などはユーザーが学習してしまうため悪影響のほうが大きくなる
    - コマーシャルが顕著
  - 比較的繰り返しの耐性が高いもの
    - 音楽
      - 視覚情報が割合として多いため

### 演出の基準

- 演出の質がどれだけ高くとも表示される回数が多いものは冗長であると感じさせる
  - 「ガチャ」の演出は特にその条件に当てはまる
    - 最初のうちは演出に感心したとしても繰り返しが行われるものであるため注目しなくなっていく
- UI のアニメーション
  - 繰り返しが多く操作の効率などを「ユーザーが学習する」場合はアニメーションのコンマ数秒が冗長となる
    - アニメーションなしとするオプションの用意
  - アニメーションの挙動として特に問題であるのはアニメーション中は操作を受け付けない仕様の場合
    - 繰り返し行われる表示においてはその都度ユーザーは「待つ」必要が発生してしまう
    - 繰り返しの表示でアニメーションを行うのであればユーザーに対し操作を許可したほうが、\
      アニメーションの価値を高める結果になると思われる
- 短縮ではなく省略が望ましい場合がある
  - ユーザーは演出などを学習してしまうことで訴求でなく悪印象につながる
- 短縮などをユーザーの操作によらせるものはストレスを生じさせるので自動化させる
  - 繰り返しの多い作業においては 2 つのユーザーのタイプでの悪影響が考えられる
    - 反応速度の遅いユーザーはその操作が時間の消費につながる
    - 反応速度の速いユーザーは繰り返しの多い価値の低い作業に対して反応するというリソースの消費を強いられることがストレスにつながる
- 大掛かりな演出は基準として想定していない。演出を行う場合もできるだけ短時間にすることを基準とする
  - 大掛かりな演出を採用する場合、最初からスキップ機能を用意する
    - スキップ後も内容を確認できる再現手段(アルバムなど)を用意する

## ゲーム理論

「おもしろみ」「体験品質」が要素の有無を見る軸なのに対し、こちらは仕組みの構造を分析するための視点。

- `情報の非対称性`
  - プレイヤー間・プレイヤーと環境間の情報格差の設計。`docs/concept/ideas/README.md` の「情報の対称性」節に対応する既存アイディアあり
- `不完全情報下の意思決定`
  - 真の成功率でなく主観的な推定値でプレイヤーに意思決定させる設計。同ファイルの「命中率(成功可能性)の可視性」節に対応
- `期待値とリスク選好`
  - 命中率など確率が絡む場面での、リスク回避/追求傾向を踏まえた設計
- `ゼロサム/非ゼロサム構造`
  - 「おもしろみ」軸の `競争`/`協調` がどちらの構造で成立しているかの裏付け
- `繰り返しゲームと評判`
  - NPC・他プレイヤーとの関係が蓄積する場面(裏切り・信頼構築)の設計
- `支配戦略・ナッシュ均衡`
  - 「これさえやれば勝てる」という単一最適解の有無をチェックするバランス分析ツール
- `メカニズムデザイン`
  - ルール設計でプレイヤー行動を誘導する視点。同ファイルの「関係性・権限構造によるゲームシステム」節と関連
