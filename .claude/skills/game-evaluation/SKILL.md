## 手順

### 1. 評価基準を読む

`docs/evaluation/README.md` を読む。

### 2. 評価対象を特定する

- 引数・会話内で対象(コンポーネント名、機能名など)の指定があればそれに従う
- 指定がなければ現在のブランチの差分(`git diff main...HEAD`)を対象とする

### 3. 軸ごとに評価する

- **おもしろみ**: 10要素(成長/挑戦/経営/工夫/探求/競争/協調/没入/自己表現/発見の驚き)のうちどれに寄与するか。全要素を満たす必要はない、寄与する要素が無いこと自体は問題でない
- **体験品質**: 演出時間・スキップ機能の要否・繰り返し耐性への影響
- **ゲーム理論**: `docs/evaluation/README.md` に該当観点が確立していれば照合。未確立の観点に無理に当てはめない

### 4. レポート形式で出力する

- 前置き・賞賛不要、指摘のみ
- 評価対象ごとに以下を簡潔に記す
  - 該当する要素
  - 懸念点(体験品質を損なう可能性など)
  - 改善提案(あれば)
- 該当要素・懸念点いずれも無い場合はその旨を明記し、無理に評価を作らない
