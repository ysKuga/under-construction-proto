# 決定事項（issue #215）

- 2026-09-22: issue #137 backlog「mob配置」から GitHub 正式サブ issue #215 として分離
- 2026-09-22: コード調査の結果、mob 配置は `ActorsLayer` 単体でなく `useActorNodeRegistry`(単一 `currentCell`/`moveActor`)・`useHexMove`・`Stage07` まで player 前提で一直線に繋がっており、当初想定より規模が大きいと判明。ユーザーへ mob の挙動要件を確認し「静止表示のみ(自己移動・EN 等の動的挙動なし)」に決定。registry の複数 actor 化・`PLAYER_ACTOR_ID` 決め打ち解消(`EnergyDebugPanel`/`canEnterCell`)は対象外、mob が自律移動する段階で別途 issue 化する
- 2026-09-22: 上記方針で実装(PR #216)。`ActorsLayer` に `mobs?: {id, cell}[]` prop を追加、player 表示とは別に `actions={[]}` `interactive={false}` の静的 `BoxBot01` を map 描画。`Stage07` は `mobs` をそのまま `ActorsLayer` へ橋渡し。`index.stories.tsx` に `WithMob` story を追加、Playwright ヘッドレスで表示確認(コンソールエラーなし)。issue #215 close
- 2026-09-22: PR #216(未マージ)に対し、mob の props threading が `docs/performance/README.md` の「内部状態は zustand store + selector 購読」方針に反するとユーザーから指摘。mob 変化(将来のランダム spawn/despawn、近い将来導入予定)のたび `Stage07` 以下全体が再レンダリング対象になる点が問題。issue #215 を再オープンし作り直し方針を決定: `ActorNodeRegistryProvider`(Context+useState、単一 `currentCell`/`moveActor`)を `stage-07/_stores/actors`(zustand vanilla store、`actors: Record<ActorId, HexCell>` + `moveActor`/`spawnActor`/`despawnActor`)へ一般化。player・mob を同一 store で一元管理する
- 2026-09-22: 作り直し完了。`ActorsLayer` は `useActorsStore` を直接 selector 購読し(`Stage07` から `currentCell`/`mobs` を props で受け取らない)、`PLAYER_ACTOR_ID` のセルへ walking/face 対応 bot、それ以外の actorId へ静的 bot を描画する。`Stage07`/`useHexMove` は `PLAYER_ACTOR_ID` の位置のみ扱い、`moveActor` 呼出し時に actorId を bind する。旧 `_contexts/actor-node-registry` は削除、呼び出し元(`stage-07/index.stories.tsx`・`proto-03/index.tsx`)を `ActorsStoreProvider`(`initialActors` prop)へ移行。store の単体テスト(`store.test.ts`)追加、Playwright ヘッドレスで Default/WithMob 両 story の表示確認(コンソールエラーなし)。spawn/despawn action は今回追加済み、実際のランダム pop トリガー実装は別途(issue #215 スコープ外)。issue #215 再 close
