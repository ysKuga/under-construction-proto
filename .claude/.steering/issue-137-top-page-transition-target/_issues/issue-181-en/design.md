# エネルギー（EN）

issue: #181（親: #137）

## 目的

経路プランニング制のステージにエネルギー（EN、移動可能燃料）を設け、パズル性（「挑戦」「工夫」）とローグライク的な資源管理の緊張感を持たせる。歩数制限から改称（decision-records.md 2026-09-16）。

## 背景・制約

- 親: [issue-137 backlog.md](../backlog.md) 該当項目からの分割（障害物・一方通行セルは別 steering）
- 方式は「実行中消費型」。予定経路は自由に組める。「実行」tick 進行ごとに1消費、道中の回復要素で回復する。事前判定型（予定経路作成時点で選択拒否）は「まだ実行していないのに拾ったことにする」必要が生じ回復アイテムと相性が悪いため不採用（decision-records.md 2026-09-16）

実装計画: [backlog.md](backlog.md)。決定事項: [decision-records.md](decision-records.md)。

## エネルギー（EN）仕様

- 保持: actor（box-bot）に属する値。Context 経由で注入する（既存 box-bot-model の Provider パターンを踏襲、props バケツリレー回避）
- 消費: 「実行」tick 進行で 1 マス移動するごとに 1 消費
- 回復手段（2種、decision-records.md 2026-09-16）
  - 回復アイテム: 道中に落ちている。踏むと携行する（即時回復しない、上限あり）。任意タイミングで「使用」して回復（固定量。1個で複数手分の回復、現実の「1食で数時間活動できる」相当の量感。決定事項 2026-09-18）
  - 回復スポット: 固定セル（ガソリンスタンド的）。据置型のため携行不可、到達すると即時回復。固定量を複数回（スポット側が在庫を持ち、枯渇しうる）
- エネルギー切れ: tick 進行中に 0 になったらそこで停止（ゴール未達）。障害物と異なり、経路選択時点では判定できない（実行してみないとエネルギー切れになるか分からない）
- UI 表示: 数値表示（`EN: 5/10`）。携行数（`携行: n/上限`）・回復スポット残り在庫（`スタンド: n/初期在庫`）も併記

## 懸念・リスク

- 初期値・上限・各回復量の具体的な数値は未確定（実装時は仮値で着手し、後日バランス調整）
- Context 注入は今回 EN 用に個別実装する。props 追加を避ける汎用的な注入手段の整備は本 issue のスコープ外、別途プロジェクト全体の課題として検討
