# 生成盤面の通行不能箇所を経路に効く位置へ置く

PR: #320（親: #315）

## 目的

`generateStage` が置く通行不能箇所（障害物・一方通行）を、開始からゴールへの経路に影響する位置へ置く。
盤面の隅等、経路に関与しない位置へ置かれてパズルとして効かない盤面を減らす。

## 背景・制約

- 親 design: [../../design.md](../../design.md)「基本構成案」
- 前段
  - #318: `generateStage`。全要素を全セルからシャッフルで取り出し、到達性のみ検証
  - #319: 開始・ゴール間の距離に下限（`minGoalDistance`）
- 通行不能箇所の意味論
  - 障害物: セルへの進入不可
  - 一方通行: 退出方向の反対側の辺が壁。跨ぐ移動は方向を問わず拒否（`_lib/one-way.ts`）
- 到達性判定は既存 `findHexPath` + `canEnterForPath` を流用する

## 基本構成案

- 配置: これまで通り通行不能箇所をランダムなセルへ置く
- 無意味判定: 1つ取り除いても開始 → ゴールの最短手数が変わらなければ無意味
  - 障害物: 盤面上の別の空きセルへ移す
  - 一方通行: 同じセルのまま壁の向きを変える
- 進入禁止判定: 開始から到達できないセルが1つでも生じたら進入禁止が発生
  - 原因の通行不能箇所を隣接する空きセルへ移す
  - ゴールへの到達性の検証はこの判定に含まれる
- 通行不能箇所は1つずつ置き、置くたびに判定する（判定対象 = 原因）
  - 一方通行の6方向すべてが無意味なら別の空きセルへ移す
- 移し直しは回数上限（`maxRelocations`）付きで繰り返す。上限に達したら従来通り盤面全体を作り直す
- 後から置いた要素で先の要素が無意味化した配置も作り直す

## 懸念・リスク

- 2つ揃って初めて迂回を生む組合せは作られない（1つずつ置いて判定するため）
- hex グリッドは最短経路が複数通りあり、1つで最短手数を延ばせる位置は少ない
  - `maxRelocations` 100 でも seed 200 件中 2 件は生成できず `DEFAULT_STAGE_LAYOUT` へフォールバックする
  - 1 seed あたり平均 30ms 程度
