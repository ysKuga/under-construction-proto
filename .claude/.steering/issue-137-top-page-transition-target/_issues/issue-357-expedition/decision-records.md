# 決定事項（find-path の本実装 expedition への移行）

- 2026-10-17: 親 #137 の backlog 項目「本実装を prototypes からコピーして設置する」を、複数 PR にわたるため #357 として切り出した。前提となる「prototypes 間の import 方針の再検討」も併せて移した（方針は親 decision-records.md 2026-10-17 本実装移行・名前）
- 2026-10-17（import 方針）: prototypes 間の import 方針を `src/prototypes/CLAUDE.md` へ追記した
  - 同系列のバージョン間ルール（若い番号からの import 可）は現状維持
  - 系列外からの import は共通置き場経由に限る。既存の直接 import は修正せず backlog へ記録する（prototypes は凍結扱いで、移行コストに見合わないため）
  - 本実装から prototypes への import を禁止する（移行方針「コピーして独立」と揃えるため）
  - 昇格はコピー前に行わない。expedition のコピー対象は変わらない
- 2026-10-17（未決事項）: コピー範囲・story・レイアウトを決めた
  - 元にする prototype は当面 proto-03 のみ
  - test はコピーする
  - story は基本構成とデバッグモードを用意する
    - デバッグモードの prop 等での切替なし
    - story 上で基本構成とデバッグ要素を組み合わせて表示
  - レイアウトは基本構成とデバッグ要素へ分ける
    - 基本構成: マップ・状態表示系
    - デバッグ要素
      - 構成: 独立したコンポーネント
      - 配置: 基本構成の下へ縦並び
    - 理由: proto-03 はデバッグ用の要素がレイアウトへ混在している
    - デバッグ要素とする対象は別途検討する
- 2026-10-17（デバッグ要素）: デバッグ要素とする対象を決めた
  - デバッグ要素
    - `ControlPanel` の表示設定（初期表示・到達済みマス表示・歩行モーション・移動可能マス表示）
    - `ControlPanel` のリセット（EN 切れ時の救済は `reset-to-checkpoint` が別途担うため）
    - `ControlPanel` の seed・生成・再生成
    - `EnergySliders`（EN 残量・EN 消費量）
    - hex-stage 組込みの調整スライダー群（tilt・移動時間・歩行周期上限・脚振り角・体の上下量）
  - 基本構成に残す
    - `WaypointSelectingIndicator`（中継点選択の完了操作に必須）
    - 中継点数・ゴール到達表示（状態表示）
    - `StageArea` 一式（hex-stage 組込みのスライダー群を除く）・`Title`・`BotBubbles`
  - 削除: 「状態表示の向きを同期」checkbox
    - 理由: 基本構成の `FacingSyncToggle` と重複（同じ設定を切り替える）
  - hex-stage のスライダー群の外出し
    - 現状: hex-stage 内部の state
    - 独立コンポーネント化には外出しが必要
    - 手段
      - 値を hex-stage の props にする（tilt は除く。進め方で handle 経由へ変更）
      - デバッグ要素がページ用 store（`display-settings`）へ書き込む
      - `stage` content が購読し hex-stage へ渡す
    - `extraSliders` prop は削除する
    - 別 PR で行う
      - 理由: store の責務が広がる
- 2026-10-17（進め方）: レイアウト分割・スライダー外出しの進め方を決めた
  - PR の順序: proto-03 本体のコピー → レイアウト分割 → hex-stage のスライダー外出し
    - 本体のコピーは独立 PR にする
      - 理由: 約 200 ファイルのコピーと構造変更が混ざると差分を追えない
    - スライダー外出しは本体のコピー後
      - 理由: ページ側の `display-settings` store を要する
  - デバッグ要素の置き場: `_contents/debug-panel/`
    - 理由: 新しい種類の置き場を作らずに済む
    - `_contents/index.tsx` からは並べず、story から使う
  - 縦並びの高さ: ルートの `h-screen` を維持し、デバッグ要素が画面外へ出るのを許容する
    - 代わりにデバッグ要素をアコーディオン状に開閉できるようにする
  - tilt は props にせず handle 経由（`Stage07Handle.setTilt`）にする
    - 理由
      - 現状 ref 直書きで再レンダリングしない
      - props 化するとドラッグ中に stage content・hex-stage が再レンダリングし続ける
    - 処理から UI への命令は imperative handle（event-ui-jurisdiction）とも整合
    - 他のスライダー（移動時間等）は決定どおり props
      - 現状も `useState`
      - 再レンダリングが増えるのは stage content のみ
