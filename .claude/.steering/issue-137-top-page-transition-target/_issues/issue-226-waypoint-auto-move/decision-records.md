# 決定事項（中継点経由の経路統合と自動移動）

- 2026-09-23: 親 #137 backlog の「自動移動」「中継点設定」残項目を GitHub サブ issue #226 として分離
- 2026-09-23: 着手順は中継点の経路統合 → 自動移動。理由: 自動移動の開始トリガーが中継点フローに依存する（選択中の誤発火回避のため明示的な開始操作が要る）。中継点の経路統合は既存プレビューのみで検証可能。自動移動が最終経路（配列）を受け取る形にすれば手戻りなし
- 2026-09-23: 最近傍法の距離は `hexDistance`（障害物を考慮しない axial 上の最小歩数）とする。理由: 区間ごとの BFS 歩数で比較すると中継点数ぶん探索が増える。「設置箇所が近い同士を接続する」目的には直線的な距離で足りる
  - 同距離の場合は設置順を優先する
  - goal は最近傍の対象に含めず、常に最後に経由する
- 2026-09-23: 経路が到達不能になる中継点（障害物セル等）は通知して設置しない。理由: 設置を許すとプレビュー経路が消え、どの中継点が原因か分からなくなる
- 2026-09-23: 経路プレビューは `goalCell` を state として保持し、`currentCell`/`waypoints`/`goalCell` から `useMemo` で導出する。経路配列そのものを state に持つと中継点の変更ごとに再計算の呼出し箇所が分散するため
- 2026-09-23: 自動移動の開始トリガーは `WaypointBubble` に併設した「実行」ボタンとする（ユーザー判断）。中継点の設置途中でも押せる
- 2026-09-23: EN 不足で経路途中の進入ができなくなった場合、その場で停止し warning トーストで警告する（ユーザー判断）。残り経路は保持しない
- 2026-09-23: 自動移動は `Stage07` 側へ汎用機能として実装し、`ref`（`Stage07Handle.followPath`）で命令する。理由: 歩行モーションの継続・停止や移動アニメーション時間（`moveDurationMs`）は `Stage07` 内部が持つため
  - 各マスの移動はクリック移動と同じ検証（`useHexMove` の `tryMove`、`canEnterCell`）を通す。EN 判定を二重に持たない
  - 1 マスごとの間隔は到着（`transitionend`）でなく `moveDurationMs` のタイマーで刻む。到着駆動だと `left`/`top` の二重通知で 2 マス進んでしまう
  - 自動移動中は `Stage07` を非対話化する
