# ゲーム評価基準策定

## 目的

ゲーム機能の実装・変更のたびに「おもしろみ」を評価できる基準を整備する。基準は以下の軸で構成する。

- おもしろみ: ゲームに含まれる面白さの種類
- 体験品質: その面白さがどう体験されるか(不快を発生させない工夫)
- ゲーム理論: メカニクス構造の分析軸(未着手)

評価を継続的に実施できるよう、基準参照・評価実行の仕組み(スキル)も合わせて整備する。

## 背景・制約

- 既存 `docs/concept/ideas/README.md` の「おもしろみ」節(6要素: 成長/挑戦/経営/工夫/探求/競争)・「よくないてん」節(繰り返し・冗長な演出)が元ネタ。内容が固まった項目として `docs/terminology/` でなく新設 `docs/evaluation/` へ切り出した(terminology は用語集、evaluation はゲーム性評価という別カテゴリのため)
- 「おもしろみ」軸へ4要素追加: 協調・没入・自己表現・発見の驚き
- 「体験品質」軸を新設。当初「快適性」名称を検討したが、「体験」を使った名称を希望する声を受け「体験品質」に決定。「おもしろみ」軸の名称は変更せず維持(体験品質を分離したことで名称の衝突感が解消するため)
- ゲーム理論的観点は未確立。既存 ideas 内の「命中率(成功可能性)の可視性」「情報の対称性」節と関連しそうだが、具体的な評価軸への落とし込みは今後の検討課題

## 決定事項

- evaluation ディレクトリは docs 直下(concept/terminology/package と並列)に配置。中身は README.md 1枚に集約(項目数がまだ少ないため。将来増えたら fun-factors/ 等へサブディレクトリ分割)
- 評価スキルは自動発火でなく手動呼出し方式を採用。誤発火リスクを避けるため、明示的な依頼(「評価して」等)があった場合のみ使用する
- 「おもしろみ」軸の名称は維持。「体験品質」軸を独立させたことで意味の混同は解消したと判断
- ゲーム理論観点、7項目採用: 情報の非対称性/不完全情報下の意思決定/期待値とリスク選好/ゼロサム・非ゼロサム構造/繰り返しゲームと評判/支配戦略・ナッシュ均衡/メカニズムデザイン。「おもしろみ」「体験品質」が要素の有無を見る軸なのに対し、ゲーム理論は仕組みの構造を分析する視点と位置づけて棲み分け
- 2026-09-12: 「おもしろみ」10要素は全て満たす必要なし、最低限いずれか1つ該当していれば良い旨を明記(find-path 実装評価で「該当要素なし」の判定が出たことを受け、基準の運用方針として明文化)

## 懸念・リスク

- ゲーム理論の7項目、現時点では列挙・簡潔な説明のみ。抽象的な理論(ナッシュ均衡等)をどこまで実務的な評価基準へ落とし込めるかは、実際に `game-evaluation` スキルで運用しながら検証が必要
- `docs/evaluation/README.md` の各要素、現時点では列挙のみで個別の判定基準(何をもって「該当する」とするか)が明文化されていない。スキル運用を重ねる中で基準の解像度を上げる必要が出る可能性がある
