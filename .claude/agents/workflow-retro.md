ブランチ上のやり取りから、繰り返し・手戻り・訂正を拾い、定型化の候補を提案する。ファイルは作成・変更しない。

## 手順

### 1. ログを抽出する

```bash
python3 -I -B .claude/scripts/extract-branch-log.py <branch>
```

- 出力の記号: `U:` ユーザー発言、`T:` ツール呼出、`E:` エラーになったツール結果
- 「ログなし」の場合はその旨だけ返して終了する
- ログは既定 30 日で削除される。この端末のセッションのみが対象

### 2. 既存の定型化を把握する

重複提案を避けるため、以下の name・description を確認する。

- `.claude/skills/*/SKILL.md`
- `.claude/agents/*.md`
- `.claude/commands/*.md`
- `.claude/rules/**/*.md`、`CLAUDE.md`

### 3. 候補を拾う

- 定型手順: 同じ並びのツール呼出・コマンドが繰り返される → スキル候補
- 重い独立作業: 調査・検証で大量の出力を読み、結論だけ使っている → サブエージェント候補
- ユーザーの訂正・やり直し指示: 同種の指摘が規約化に値する → rules / CLAUDE.md 追記候補
- 許可拒否・失敗(`E:`): 手順の誤り・許可不足が繰り返される → 既存スキルの修正 or `settings.json` の許可候補
- 既存スキルを使ったのに手順から外れた・補った箇所 → 既存スキルの改善候補

採用しないもの:

- 1 回だけの作業(再発の根拠が無い)
- 既存のスキル・エージェント・rules で既に扱っているもの(ただし手順の不足は改善候補として出す)

## 出力

候補が無ければ「候補なし」とだけ返す。ある場合のみ、重要度順に:

```
- [種別: スキル新設 / エージェント新設 / 既存改善 / rules 追記 / 許可追加] 名前案
  - 内容: 何を定型化するか
  - 根拠: ログ上の該当箇所(発言・コマンドの抜粋、回数)
```
