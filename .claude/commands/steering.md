## 引数

`$ARGUMENTS`: `[issue-{番号}|pr-{番号}] [タイトル]`

- 先頭が `issue-{番号}` または `pr-{番号}` の場合、そのプレフィックスをディレクトリ名に使う
- 無ければ従来通り日付プレフィックス
- タイトル部分が空の場合、ユーザーにタイトルを求める

命名の使い分けは [.claude/rules/steering.md](../rules/steering.md) 参照。

## 手順

### 1. ディレクトリ名決定

- `$ARGUMENTS` 先頭が `issue-{番号}` または `pr-{番号}` にマッチする場合:\
  `issue-{番号}-[タイトル]` / `pr-{番号}-[タイトル]` 形式でディレクトリ名を構成する。\
  例: `issue-96-app-top-page-readme-style` / `pr-101-box-bot-display-tuning`
- マッチしない場合(従来通り):

  ```bash
  date +%Y%m%d
  ```

  `YYYYMMDD-[タイトル]` 形式でディレクトリ名を構成する。\
  例: `20260610-add-auth-feature`

いずれもスペースはハイフンに置換する。

### 2. ディレクトリ作成

作業中のプロジェクトルートに `.claude/.steering/[決定したディレクトリ名]/` を作成する。

```bash
mkdir -p .claude/.steering/[決定したディレクトリ名]
```

### 3. design.md 生成

以下のテンプレートで `.claude/.steering/[決定したディレクトリ名]/design.md` を作成する。

**注意:** このファイルはリポジトリで管理される。API トークン・パスワード・個人情報などのセンシティブな情報は記載しないこと。

```markdown
# [タイトル]

<!-- issue-XX / pr-XX プレフィックスの場合のみ記載: issue: #XX または PR: #XX -->

## 目的

<!-- この作業で達成すること -->

## 背景・制約

<!-- 判断の前提となる情報 -->

## 実装計画

- [ ]

## 決定事項

<!-- 検討・決定した内容のログ -->

## 懸念・リスク

<!-- 注意点、未解決の問題 -->
```

### 4. recent.md に追記

`~/.claude/recent.md` に作業エントリを追記する。ファイルが存在しない場合は自動作成される。

```bash
pwd
```

```bash
echo "- $(date +%Y-%m-%d) $(pwd): [タイトル] → .claude/.steering/[決定したディレクトリ名]/" >> ~/.claude/recent.md
```

`[タイトル]` と `[決定したディレクトリ名]` は実際の値に置換すること。

### 5. 完了通知

作成したディレクトリパスとファイルをユーザーに通知する。
