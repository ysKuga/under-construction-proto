# レイアウト変更前の合意

画面レイアウト（並べ方・上下関係）変更前、以下をユーザーへ提示し合意してから実装する。

- 対象要素: 指示の呼称（「status」「slider」等）が指すコンポーネント名
  - 呼称が複数の要素に当てはまる場合、候補を挙げて確認する
- 変更後の並び: 簡単な図か文章
  - 例: 「上段: `Stage`・bot の状態表示を横並び / 下段: 調整スライダー」
- 影響を受ける周辺要素: 位置が変わる要素（ゴール到達表示等）
- 要素の形を変える場合
  - 占める範囲: 1 段を使い切るか、他の要素と横に並べるか
  - 形: 正方形・高さ固定・中身に合わせる等
- ページ内容へ余白を付ける・残す場合
  - 外側（body・layout・Storybook の padding）の余白と重ならないか
- 他の要素へ重ねる UI（設定アイコン・ポップオーバー等）を置く場合
  - 属する要素（bot・ステージ等）と置く隅
  - ポップオーバーの開く向き・揃える端
  - ポップオーバーの中身の並べ方（見出しとスライダーの改行・幅）
- 表示領域（盤面・scene 等、中身の一部を映す枠）を変える場合
  - 大きさ: 固定か、中身に合わせて伸び縮みさせるか
  - はみ出しの扱い: 切る・スクロール・縮小のどれか
  - 映す対象: bot を追うカメラか、全体を収めるか
  - 指示に含まれる確認用の条件（`GRID` を 10×10 にする等）: 何を確かめるためのものか

## 確認

`story-verifier` へ渡す期待値に以下を含める（[CLAUDE.md](../../../CLAUDE.md)「実ブラウザ動作確認」）。

- 変更後の並び
- 周辺要素の位置
- 上下の段の左右の端が揃っているか（揃えない意図なら、その旨）

ブレークポイントで並べ方を切り替える変更の場合、以下も含める。

- 確認する幅
  - 狭い画面（375px）
  - 境界の両側（`md` なら 767px・768px）
  - 広い画面（1280px）
- 狭い画面での観測値
  - 要素の画面からのはみ出し
  - 文字の 1 文字ずつの縦の折返し（列の縮み）

## 理由

expedition のレイアウト分割（PR #369）で、「status」を新設の `StatusPanel`（実際は bot の状態表示）、「スライド」をデバッグ要素と取り違えた。\
訂正 4 回、revert 1 回を要した。

調整スライダーの設定アイコン（PR #375）で、アイコンの位置を 3 回置き直した（bot 右上 → ステージ右上 → 床の左下）。\
属する要素・隅・ポップオーバーの揃え方を、着手前に確認していなかった。

expedition の並べ方の切替（PR #398）で、375px・1280px のみ確認を依頼した。\
375px でマスの情報が 40px まで縮む崩れが見つかり、境界の幅・折返しの観点を再確認時に足した。

expedition の表示領域（PR #400）で、表示領域を中身（傾けた床）に合わせて伸び縮みさせる前提で実装した。\
ユーザーの意図は以下だった。

- 大きさ固定（テレビの画面のように）
- スクロールなし
- bot を追うカメラ

10×10 の指示も、はみ出しを作るための条件だった。\
実装を捨てて作り直した。

expedition のスマホの幅での bot の状態表示（PR #402）で、状態表示を 1 段使う横一列のバーで実装した。\
ユーザーの意図は、小さい正方形にしてマスの情報と横並びにすることだった。\
占める範囲・形を着手前に確認していなかった。

同じ PR で、375px の表示領域（343px）が下の段（311px）より左右 16px ずつ広かった。\
ページ内容の `px-4` が外側の余白と重なっていた。\
`story-verifier` は観測値を返していたが、期待値に段の揃いを含めておらず、問題として扱わなかった。
