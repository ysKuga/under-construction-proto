# レイアウト変更前の合意

画面レイアウト（並べ方・上下関係）変更前、以下をユーザーへ提示し合意してから実装する。

- 対象要素: 指示の呼称（「status」「slider」等）が指すコンポーネント名
  - 呼称が複数の要素に当てはまる場合、候補を挙げて確認する
- 変更後の並び: 簡単な図か文章
  - 例: 「上段: `Stage`・bot の状態表示を横並び / 下段: 調整スライダー」
- 影響を受ける周辺要素: 位置が変わる要素（ゴール到達表示等）
- 他の要素へ重ねる UI（設定アイコン・ポップオーバー等）を置く場合
  - 属する要素（bot・ステージ等）と置く隅
  - ポップオーバーの開く向き・揃える端
  - ポップオーバーの中身の並べ方（見出しとスライダーの改行・幅）

## 確認

`story-verifier` へ渡す期待値にも、変更後の並びと周辺要素の位置を含める（[CLAUDE.md](../../../CLAUDE.md)「実ブラウザ動作確認」）。

## 理由

expedition のレイアウト分割（PR #369）で、「status」を新設の `StatusPanel`（実際は bot の状態表示）、「スライド」をデバッグ要素と取り違えた。\
訂正 4 回、revert 1 回を要した。

調整スライダーの設定アイコン（PR #375）で、アイコンの位置を 3 回置き直した（bot 右上 → ステージ右上 → 床の左下）。\
属する要素・隅・ポップオーバーの揃え方を、着手前に確認していなかった。
