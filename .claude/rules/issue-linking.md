# issue 紐づけルール

## 対象

機能開発(新規ブランチでの `feat` 相当の作業着手時)。`fix`/`docs`/`chore` 等の小規模作業は対象外。

## タイミング

新規ブランチ作成前、対応 issue の有無を確認する。

## 手順

- 対応 issue が既知の場合、ブランチ名先頭に issue 番号を含める(例: `50-add-auth`)。コミットメッセージへの番号付与は lefthook が branch 参照から自動処理する([コミットルール](commit.md))
- issue が未定の場合、ユーザーへ確認する
  - 対応 issue があるか
  - なければ `gh issue create` で新規作成するか
- 作成する場合、ユーザー承認を得てから `gh issue create` を実行し、発行された番号をブランチ名に反映する
- 不要と判断された場合、issue 紐づけなしで作業を進める
